# UI / UX SPEC — Finance Hub

## Общий принцип

Finance Hub должен выглядеть частью текущего FunPay Funcy, а не отдельной админкой.

Использовать:
- существующие CSS variables `--fpt-*`;
- текущую Material Symbols иконографику;
- текущие радиусы/карточки/hover;
- существующий accent color;
- текущую ширину popup/content area.

Не использовать внешнюю chart library, если текущие SVG-графики проекта решают задачу.

## Обзор — сетка

Использовать 12-column grid.

### Row 1 — KPI, 4 × 3 columns

1. **Выручка**
2. **Чистая прибыль**
3. **Заказы**
4. **Средний чек**

Карточка `Чистая прибыль`:
- крупная сумма;
- margin;
- coverage себестоимости;
- если coverage < 100%, иконка info.

### Row 2 — потенциал, 4 × 3 columns

1. **Потенциальная выручка**
2. **Потенциальная прибыль**
3. **Стоимость склада**
4. **Активные лоты / единицы**

Если есть unlimited/неизвестный stock:
- не включать в monetary totals;
- показывать badge `+ N лотов без остатка`.

### Row 3

8 columns:
- основной line chart.

4 columns:
- donut `Прибыль по категориям`
или, если profit coverage низкий:
- `Выручка по категориям`.

Chart metric tabs:
- Выручка
- Прибыль
- Заказы

### Row 4

6 columns:
- Топ товаров.

6 columns:
- Топ категорий.

### Row 5

12 columns:
- последние операции / последние заказы в зависимости от активного tab.

## Продажи

Переиспользовать текущие режимы `sales_modes.js`, но отрисовывать в Finance Hub.

Блоки:
- cards;
- chart;
- diagrams;
- detailed tables;
- полный список по drill-down.

Старую семантику period/status/sort не менять без необходимости.

---

## Покупки

Визуально симметричны продажам.

Важно:
- не путать `Покупки` пользователя с `Себестоимостью товара`;
- покупки — реальные операции FunPay пользователя;
- себестоимость — пользовательская аналитическая метаинформация конкретного лота.

---

## Прибыль

Основной смысл — realised profit.

KPI:
- Чистая прибыль;
- Себестоимость проданного;
- Маржа;
- ROI;
- Orders with known cost;
- Coverage.

Chart:
- Revenue vs Profit (две линии) ИЛИ metric toggle.
- Не строить profit для unknown-cost orders.

Tables:
- прибыль по товару;
- прибыль по категории;
- самые прибыльные позиции;
- самые низкомаржинальные позиции.

Для строк без cost:
`Себестоимость не указана` + action `Указать`.

# Поле себестоимости на странице FunPay

## Где

На:
- `Редактирование предложения`
- `Добавление предложения`

Расположение:
сразу после блока цены продавца / `Цена покупателю`, но до второстепенных инструментов.

## Визуальный вид

Отдельная плашка FunPay-compatible:

- icon: `payments` / `inventory_2`
- title: **Себестоимость**
- subtitle: `Для аналитики FunPay Funcy. Видно только вам.`
- numeric input;
- currency label/select;
- live preview.

Пример:

Себестоимость
[ 600,00 ] ₽
Для аналитики FunPay Funcy. На FunPay не отправляется.

При текущей цене:
Получите: 940 ₽
Прибыль: 340 ₽
Маржа: 36,2%

## UX

- Значение сохраняется локально.
- Изменение поля НЕ должно мутировать native FunPay form payload.
- Не делать поле required.
- `0` и пусто = себестоимость неизвестна, а не бесплатный товар.
- Для существующего лота значение привязывается к `offerId`.
- Для нового лота до получения `offerId` использовать tab-scoped draft через `sessionStorage`.
- После redirect/save, когда появился `offerId`, draft переносится в постоянное хранилище.
- После переноса draft удаляется.
- При клонировании собственного лота cost можно копировать только если источник точно известен.
- При копировании чужого лота себестоимость никогда не наследовать.

---

## Loading / empty / error states

Каждый tab должен иметь:
- skeleton/loading;
- empty state;
- retry;
- last-updated;
- отсутствие данных не должно ломать весь Finance Hub.

---

## Accessibility

- visible focus;
- кнопки как `<button>`;
- графики не должны быть единственным источником информации;
- tooltip значения дублируются текстом/таблицами;
- никакой информации только цветом.
