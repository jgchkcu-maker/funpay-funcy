# Самостоятельная проверка Funcy 0.9.11

Живые проверки в этой задаче отключены по просьбе пользователя. Этот список описывает будущую приёмку, а не выполненные действия. Используйте демонстрационный товар, который не жалко показать в тестовом чате. Не публикуйте реальные ключи и сессии в отчёте.

## Подготовка

1. Сохраните экспорт настроек и резервную копию текущего профиля Chrome. Экспорт настроек не заменяет резервную копию хранилища сессий аккаунтов и IndexedDB.
2. Для первичной проверки создайте отдельный профиль Chrome, откройте `chrome://extensions`, включите режим разработчика и нажмите «Загрузить распакованное расширение». Выберите `dist/funcy-0.9.11-staging` из этого проекта. ZIP для магазина сам по себе через эту кнопку не устанавливается; если staging отсутствует, распакуйте ZIP в отдельную папку.
3. Убедитесь, что указаны Funcy, версия 0.9.11, Chrome 120+. Не запускайте одновременно старую и новую автоматику для одного аккаунта. В новом профиле она должна быть выключена.
4. Без входа проверьте открытие popup по иконке. Затем войдите в FunPay и откройте меню Funcy. Просмотрите лоты, автоответы, выдачу, журнал заказов, аккаунты, оформление, звуки и поддержку. Проверьте светлую/тёмную тему и узкое окно.
5. Для обновления существующего **unpacked** экземпляра используйте тот же путь и ID расширения: сначала резервная копия папки и профиля, затем новые runtime-файлы и «Обновить». Установка из другого пути создаёт другой ID и не доказывает миграцию старых данных. Для версии из магазина проверка обновления требует подписанного обновления с тем же ID; unpacked-копия этого не подтверждает.

## Настройки, ресурсы и сеть — без покупки

* После обновления с 0.9.9 должны остаться аккаунты, заметки, шаблоны, настройки и пользовательский звук. Бывший точный дефолтный фон превращается в градиент; собственный фон остаётся. Старый VK/TG/iPhone/Discord/WhatsApp становится стандартным звуком FunPay, своя мелодия остаётся.
* Откройте темы: должны работать переключатель, цвета, свой фон, предпросмотр, «Применить» и «Отменить». У каталога будет сообщение о проверке прав. Старые непроверенные обои недоступны, новые записи JSON не включаются автоматически.
* Выберите перевод демонстрационного названия/описания. В DevTools страницы/worker → Network проверьте запросы к `translate.googleapis.com`; передаются выбранные поля. Ошибки перевода не должны запускать отключённый AI-сервис.
* Откройте темы с Network: JSON запрашивается с `raw.githubusercontent.com` из content script. Убедитесь, что нет CORS-ошибки. Это ещё не проверялось на живом FunPay. При скрытом каталоге изображений из него загружаться не должно.
* Нет обращений к `fptools.onrender.com`, `fptools-ai-server.vercel.app` и `fpt-descs.starobinskiy01.workers.dev`. Нет скрытой подписи пользователей и запроса поставить пять звёзд на чужой карточке.
* Выключите все функции автоматики. В DevTools worker можно выполнить `await chrome.alarms.getAll()` для осмотра: нет `fpToolsEngineHeartbeat`, `fpToolsEngineContinue`, `fpToolsAutoResponder`, `fpToolsAccountKeepalive`. Предметные задания включённых функций нужно оценивать отдельно. В Network не должно быть регулярного опроса чатов. Сохранённые аккаунты не обходятся ежедневно; ручное обновление аккаунта остаётся.

## Автоответчик — обычный чат

1. Добавьте редкое тестовое ключевое слово и ответ. Включите автоответчик и дайте ему выполнить исходный проход: старые сообщения не должны вызвать рассылку.
2. Пусть другой участник отправит слово. Запишите время отправки и получения ответа. При открытой странице сигнал может ускорить проход; при закрытой вкладке проверка идёт alarm. Двойного ответа на один ID сообщения быть не должно.
3. Отправьте три разных сообщения с этим словом подряд до следующего прохода. Должно прийти три ответа по порядку, без потерь и дублей. Повторите с двумя одинаковыми сообщениями: у них разные ID, каждое должно обрабатываться отдельно.
4. Покупатель отправляет слово, затем вы быстро отправляете собственный текст, содержащий это же слово. Ответ должен прийти только на сообщение покупателя. Повторите со словом внутри демонстрационной выдачи.
5. Покупатель вручную пишет «оплатил заказ #ABCDEFGH». Это обычное сообщение: оно не должно создавать системную оплату или запускать выдачу. Обычное правило по словам может отвечать на этот текст.
6. Во время паузы Chrome отправьте несколько сообщений, затем возобновите работу. Сообщения после исходной границы должны дочитаться. Если окно не закрывает пропуск или автор не распознан, в разделе автоответов должно появиться пояснение; курсор не должен перескакивать на последнее превью.
7. После смены аккаунта проверьте отсутствие ответов в чатах предыдущего аккаунта. При первом включении 0.9.11 старые превью устанавливают новую границу: историческая переписка не вызывает рассылку.
8. У нового чата после исходного прохода первое сообщение должно обработаться после проверки начала истории. При большом числе чатов работа продолжается следующими проходами: лимит 8 чатов, 50 обработанных сообщений и 3 страницы истории за проход, пачки до 4 чатов. Это локальные бюджеты, а не доказанные лимиты FunPay.
9. Если после прерывания появилась надпись «результат ответа неизвестен», сначала проверьте реальную переписку. Автоматического повтора зарезервированного сообщения не будет. После ручного решения можно использовать существующий сброс истории автоответчика в «Переносе настроек» либо выключить все сценарии автоответов и выдачи и включить нужные заново: это устанавливает новую исходную границу для всех чатов. Не используйте сброс для автоматической повторной отправки.

## Один согласованный заказ

Используйте свой разрешённый тестовый лот и отдельного покупателя, действующего по правилам площадки. Заказ и оплату выполняйте сами. Сначала проверьте шаблон, затем при необходимости товар из FunPay.

1. Шаблон: `Часть A. Количество: {quantity}$sleep=60Часть B`. Покупайте одну или несколько единиц по согласованному сценарию. Должна быть одна инструкция с правильным количеством, а не повтор всего шаблона N раз.
2. После оплаты покупатель сразу пишет в чат. Сверка должна найти оплату, даже если превью её вытеснило. Запишите фактическую задержку, номер заказа, состояние частей и отсутствие дублей. Старые оплаченные заказы, неизвестные даты и пограничная минута не должны автоматически приниматься в выдачу.
3. После части A закройте DevTools worker и остановите worker через `chrome://serviceworker-internals` (если эта страница доступна в вашей версии), либо перезапустите Chrome. После срока часть B должна отправиться один раз. Alarm может опоздать; точность до секунды не требуется.
4. Отдельно проверьте выключение выдачи, смену аккаунта и удержание до наступления части B. Она не должна отправиться. При реальном возврате новые части тоже должны остановиться. Не оформляйте лишний возврат только ради проверки без согласования с покупателем.
5. Для обрыва POST используйте только безвредный демонстрационный текст. Остановите worker во время запроса. После восстановления состояние `sending` должно стать `uncertain`, автоматического повтора нет. Вначале сверяйте реальный чат, и лишь затем принимайте ручное решение «отправить ещё раз». `accepted` тоже не означает однозначного отказа.
6. Добавьте ключевое слово автоответчика в свою выдачу: самоответа быть не должно благодаря проверке ID автора. Выдача должна совпасть с подготовленным текстом без добавления U+2061 или U+2064. Обычные автоответы сохраняют старую метку; проверяйте именно сообщение с товаром.

### Проверка кодпоинтов копируемого товара

Скопируйте демонстрационный товар и вставьте его в локальный временный текст/поле. Для проверки в DevTools можно вручную задать **несекретную** строку:

```js
const copied = 'вставьте демонстрационный текст';
Array.from(copied, ch => 'U+' + ch.codePointAt(0).toString(16).toUpperCase().padStart(4, '0'));
```

В 0.9.11 автоматическая выдача не добавляет U+2061/U+2064. Сравните массив кодпоинтов демонстрационного товара до отправки и после копирования из чата. Собственные невидимые символы товара должны сохраниться. Обычные автоответы по-прежнему отмечаются U+2061; это отдельные сообщения.

## Сверка, длина и badge

* Для проверки большого обхода подготовьте в контролируемой среде больше заказов/страниц, чем бюджет одного прохода. После остановки worker продолжение должно сохраниться, завершённая граница не должна перескочить через остаток. Автотесты с синтетическими данными уже покрывают этот сценарий; много реальных покупок для него не требуется.
* До отправки всего шаблона обнаруживается строка длиннее 1000 символов, даже если она во второй части. Первая часть при этом не уходит. Длинный список целых строк делится на сообщения, ключ или логин не разрезается. 1000 — рабочий параметр, максимальный лимит FunPay не доказан.
* При проблемном заказе появляется badge на иконке. После ручного разрешения он пересчитывается; при смене аккаунта показывает проблемы нового аккаунта. Сохранённая ожидающая часть не должна становиться ошибкой только из-за паузы.

## Фон и задержки

Повторите один безвредный чатовый сигнал с открытой вкладкой, с закрытой вкладкой и после сна компьютера. Измеряйте отдельно; DevTools worker во время проверки его засыпания должны быть закрыты. Убедитесь в отсутствии пачки повторных выдач после восстановления. Unpacked-режим Chrome допускает послабления для alarms, поэтому эти измерения не доказывают поведение подписанного релиза. Перед подачей повторите на экземпляре, максимально близком к установленному из магазина.

Форма результата: версия Chrome и расширения, способ установки, сценарий, ожидаемое/фактическое поведение, задержка, обезличенный снимок журнала. Публичный URL политики, актуальные снимки карточки и подтверждение прав на брендовые исходники нужны отдельно от ZIP.

## Скроллбар попапа

1. Включите голубую тему, откройте длинную страницу меню и разверните группы боковой навигации. Ползунки попапа и полей ввода должны быть нейтрально-серыми, при наведении немного светлее.
2. Измените цвет ползунка страницы в редакторе темы и сохраните. Цвет страницы и её предпросмотра должен измениться; у попапа — сохраниться.
3. Проверьте светлую и тёмную тему, узкое окно, прокрутку колёсиком, перетаскивание ползунка и горизонтальную прокрутку. Геометрия меню при смене цвета не должна меняться. В режиме высокой контрастности используются системные цвета.

## Протокол и границы проверки

Код читателя сверялся с закреплённым исходным кодом FunPayAPI в FunPayCardinal, но реальные обезличенные ответы FunPay в задаче не получены. Локальные тестовые ответы синтетические. При несовпадении реального формата чтение должно остановиться с пояснением; не снимайте проверки автора и ID ради обхода ошибки. Для расследования достаточно обезличенных полей ID/author и структуры HTML; cookies, токены, имена, текст покупателя и товар в отчёт не включайте.
