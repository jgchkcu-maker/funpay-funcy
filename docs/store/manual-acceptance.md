# Самостоятельная проверка Funcy 0.9.12

Этот список описывает процедуру приёмки и сценарии проверки расширения, включая обновления версии 0.9.12. Используйте демонстрационный товар и обезличенные данные, которые не жалко показать в тестовом чате. Не публикуйте реальные ключи, сессии и переписку в отчётах.

## Подготовка

1. Сохраните экспорт настроек и резервную копию текущего профиля Chrome. Экспорт настроек не заменяет резервную копию хранилища сессий аккаунтов и IndexedDB.
2. Для первичной проверки создайте отдельный профиль Chrome, откройте `chrome://extensions`, включите режим разработчика и нажмите «Загрузить распакованное расширение». Выберите `dist/funcy-0.9.12-staging` (собранный через `tools/build-store.ps1`). ZIP для магазина сам по себе через эту кнопку не устанавливается; если staging отсутствует, соберите его скриптом `tools/build-store.ps1`.
3. Убедитесь, что указаны имя **Funcy**, версия **0.9.12**, минимальная версия Chrome 120+. В новом профиле автоматические функции по умолчанию выключены.
4. Без входа проверьте открытие popup по иконке. Затем войдите в FunPay и откройте меню Funcy. Просмотрите лоты, автоответы, выдачу, журнал заказов, аккаунты, оформление, звуки и поддержку. Проверьте светлую/тёмную тему и узкое окно.

## Новые проверки версии 0.9.12

### 1. Перевод в чатах (единая очередь и предсказуемое состояние)
* **Видимость кнопки перевода:** Откройте чат с любым собеседником (в том числе когда в сайдбаре язык собеседника не указан, либо собеседник русскоязычный, либо сайдбар свёрнут). При наведении на группу сообщений рядом с кнопкой «Ответить» (слева от даты) должна отображаться кнопка «Перевести сообщение».
* **Ручной перевод сообщения:** Нажмите кнопку перевода. Внизу сообщения должен появиться разделитель и текст перевода, отрендеренный безопасно (без HTML-тегов). При повторном клике перевод снимается.
* **Совпадение языка:** При попытке перевести сообщение, текст которого совпадает с результатом перевода (например, русский текст при переводе на русский), перевод считается успешным, но лишний дублирующий блок под сообщением не создаётся.
* **Режим «Включить перевод» в меню чата (три точки):** Включите режим перевода в чате с большим количеством сообщений (30–100 сообщений). В DevTools Network проверьте: запросы к `translate.googleapis.com` идут строго последовательно (concurrency = 1) с интервалом не менее 300 мс, без шквала одновременных сетевых обращений и ошибок 429.
* **Переключение контекста:** Включите режим перевода и быстро переключитесь на другой диалог или выключите перевод. Запросы предыдущего чата не должны вставлять переводы в новый чат или оставаться на экране.
* **Безопасность цитирования и экспорта:** При наличии переведённых сообщений нажмите «Экспортировать чат» в меню или кнопку цитирования/ответа. Экспортируемый текст и цитата должны содержать только оригинальные сообщения без текста перевода (`.fp-trans-wrap`).

### 1a. Согласие на перевод
* **Первый перевод:** в новом профиле нажмите «Перевести сообщение». Должно открыться окно «Перевод через Google Translate». В DevTools Network до нажатия «Разрешить» нет запросов к `translate.googleapis.com`.
* **Отказ:** нажмите «Отмена». Перевод не появляется, запросов нет. Режим «Включить перевод» в меню чата после отказа не включается и снова показывает окно.
* **Разрешение:** нажмите «Разрешить». Перевод работает и дальше без повторного вопроса, в том числе в поле лота («Перевод») и при копировании лота со страницы заказа.
* **Экспорт настроек:** файл экспорта не содержит `fpToolsTranslateConsentAt`.

### 2. Согласование цены лота и защита от ошибок
* **Приоритет живого поля «Цена покупателю»:** Откройте страницу редактирования любого лота (`/lots/offerEdit`). При наличии рублёвого способа оплаты в таблице FunPay живое поле «Цена покупателю» инициализируется, рассчитывает комиссию, а резервная кнопка «Рассчитать, чтобы получить эту сумму» скрывается.
* **Двусторонний пересчёт:** Введите новую цену продавца — поле покупателя должно мгновенно обновиться. Введите желаемую цену покупателя — поле цены продавца должно пересчитаться с округлением до копеек и сгенерировать события `input` / `change` для формы FunPay.
* **Отсутствие рублёвого способа оплаты:** Если в категории нет рублёвых способов (только USD/EUR), живое поле выводит статус недоступности комиссии без искажения цены продавца, а резервная кнопка «Рассчитать, чтобы получить эту сумму» остаётся доступной пользователю.
* **Защита массового редактора лотов от валюты (chips):** Откройте массовый редактор лотов. Валютные предложения (чипсы) отфильтрованы из списка. Если валютный лот был передан явно, операция пропускает его с понятной причиной («Валютные предложения не поддерживаются массовым редактором лотов») без остановки всей очереди.

### 3. Магазинный манифест и разрешения
* В `dist/funcy-0.9.12-staging/manifest.json` отсутствуют `raw.githubusercontent.com`, `fonts.googleapis.com` и `fonts.gstatic.com`.
* В `dist/funcy-0.9.12-staging/manifest.json` отсутствует строка `update_url` (CWS управляет обновлениями автоматически).
* В корневом `manifest.json` для локального использования сохранён исходный канал `update_url`.
* Пакет `dist/funcy-0.9.12.zip` валидируется скриптом `tools/validate-store.cjs` без ошибок.

## Инструкции для проверяющего модератора Chrome Web Store

1. **Суть расширения:** Funcy расширяет пользовательский интерфейс платформы FunPay для авторизованных продавцов: ускоренное управление лотами, аналитика заказов, автовыдача товаров покупателям, безопасный перевод переписки.
2. **Требования к среде:** Расширение активируется на страницах домена `funpay.com` при наличии авторизованной сессии пользователя.
3. **Демонстрация:** Проверяющему модератору рекомендуется ознакомиться с обезличенным демонстрационным видеороликом, приложенным в поле *Detailed Instructions for Reviewers* в консоли Chrome Web Store.
