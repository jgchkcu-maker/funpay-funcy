## Изменения

* Превью сообщает о новом ID, затем читатель получает сообщения. ID сохраняются строками без потери точности; обработка идёт по возрастанию ID. Противоречивые повторы блокируются.
* Автор берётся только из поля протокола: текущий аккаунт — собственное сообщение, 0 — системное, другой числовой ID — собеседник. Неизвестный автор блокирует продвижение. Имена и невидимые метки не определяют автора. Текст покупателя, похожий на оплату, остаётся обычным сообщением.
* Курсоры, очередь, паузы и резервирования хранятся по аккаунтам. Записи и внешние эффекты проверяют аккаунт/epoch. Новый runtime не экспортируется и не принимается из импорта; синхронизация настроек не переносит его другому аккаунту.
* Первый проход устанавливает исходную границу без рассылки по старой переписке. Позднее обнаруженный чат дочитывается до общей исходной границы ID или своего начала. Модель общего порядка ID требует проверки на живом протоколе.
* Пропуск дочитывается с сохранением буфера между проходами. Курсор не перескакивает через неизвестного автора или незакрытый пропуск. Перед обработкой чужого сообщения сохраняется резервирование; прерванная попытка не повторяется автоматически. Системный заказ перед продвижением курсора проходит общий журнал выдачи.
* Один читатель на аккаунт, пачки до 4 чатов; за проход до 8 чатов, 50 обработанных сообщений, 3 запросов истории, проверка бюджета 20 секунд между действиями. Уже начатый запрос или сценарий может завершиться позже. Паузы для 403/429, сетевых и протокольных ошибок сохраняются; немедленных повторов чтения нет. Это локальные бюджеты, а не доказанные пределы сервиса. Лимит 1000 чатов и до 1000 сообщений в буфере одного пропуска; превышение остаётся видимой остановкой.
* Проблемы чтения и неизвестный исход видны в разделе автоответов. Существующий сброс истории устанавливает новую границу; перед ним нужно вручную проверить переписку. Служебная запись курсора не запускает новый проход движка.
* Автовыдача использует отдельный строгий отправитель без добавления U+2061/U+2064. Собственные символы товара сохраняются. Обычные автоответы остаются отмеченными. Без проверенной исходной границы результат отправки остаётся accepted. Сам отправитель входящие курсоры не меняет. Перед отправкой картинки повторно проверяется аккаунт; POST загрузки и ответа на отзыв не повторяются автоматически.
* Ползунки меню, навигации и полей попапа имеют фиксированный цвет #737985, при наведении #8a909a. Геометрия и overflow не менялись. Цвет страницы и её предпросмотра остаётся настраиваемым; высокая контрастность использует системные цвета.

Поля runner/history сверены по закреплённой ревизии c09dd13be25072bb3d5cdbba33d1e0d70e477710 FunPayCardinal: [account.py](https://raw.githubusercontent.com/sidor0912/FunPayCardinal/c09dd13be25072bb3d5cdbba33d1e0d70e477710/FunPayAPI/account.py), [updater/runner.py](https://raw.githubusercontent.com/sidor0912/FunPayCardinal/c09dd13be25072bb3d5cdbba33d1e0d70e477710/FunPayAPI/updater/runner.py). Для подачи в магазин отдельно нужны публичная политика, актуальные снимки и подтверждение прав на брендовые исходники. Публикация, push, заказы и оплаты не выполнялись.
