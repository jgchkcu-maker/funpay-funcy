# Проверки и их границы

## Исследование исходников

- Получено 718 уникальных текстовых объектов GitHub; 525 Python-файлов статически разобраны через AST/текст. Повторы Git blob объединены, содержимое сверено по SHA-1 формата Git blob: несовпадений 0.
- В 4 исходниках найдены синтаксические ошибки. Ошибка не исправлялась и не замалчивалась; неразбираемый AutoSteamGift получил неизвестный статус. Остальные проблемные файлы относятся к облачной копии бота.
- Проверены импорты, обработчики BIND_TO_*, определения функций, домены, признаки протоколов и состояния. Автоматические признаки используются для навигации; вердикты назначены отдельно по сценарию, а не по наличию Python/import.
- Вложения Telegram без байтов не сравнивались по hash. Их одинаковые имена — предварительные семейства, а не доказанные копии GitHub-файлов.
- Код чужих плагинов не импортировался, не устанавливался через pip и не выполнялся.
- Для всех 130 семейств добавлен [индекс сценариев](scenario-details.md): ключи настроек/схем, обработчики событий, операции, точки хранения и обработки ошибок. Структурно сопоставлены 33 отличающихся варианта. Имена функций и наличие `except` служат указателями в коде и не выдаются за доказательство успешного восстановления.
- Для 19 защищённых публичных ZIP сверены SHA-256 с каталогом и состав файлов. Наличие PyArmor runtime и `.pyd` не раскрывает бизнес-логику; эти релизы сохраняют вердикт «недостаточно данных». Установщики, защищённое ядро и нативные модули не выполнялись.

## Изолированный браузерный эксперимент

Chrome for Testing **151.0.7922.34**, новый временный профиль, синтетическое MV3-расширение. Вкладок FunPay нет. Все тестовые сетевые запросы — к собственному loopback HTTP-серверу на 127.0.0.1 со случайным портом; покупок, сообщений, реальных ключей и кошельков нет.

| Проверка | Наблюдение |
|---|---|
| Worker HTTP без заголовка CORS от сервера, но с host permission | True |
| Ручной Cookie в fetch | Отброшен: None |
| Cookie jar + credentials:include | synthetic=jar |
| HMAC-SHA1 / RFC 6238, timestamp=59 | 94287082 = ожидаемому 94287082 |
| Steam-алфавит поверх HMAC, синтетический shared secret | PV9M4 = независимому Python-вектору PV9M4 |
| DNR User-Agent, ограниченный initiator расширения | CardinalPortabilityProbe/1.0 |
| chrome.sockets / process / require в worker | undefined / undefined / undefined |
| Остановка через ServiceWorker.stopWorker | stopped действительно наблюдён: True |
| Новый экземпляр worker | Новый instanceId при сохранённом checkpoint: True |
| Общий результат | **True** |

`Target.closeTarget` и изменение target ID не используются как самостоятельное доказательство рестарта: Chrome может сохранять идентификатор target. Проверка использует событие stopped и новый случайный instanceId в JavaScript. Исходный JSON — [probe-results.json](checks/probe-results.json), воспроизводимый скрипт — [probe.cjs](checks/probe.cjs).

Для повторения нужны Node, Playwright и Chromium/Chrome for Testing с загрузкой unpacked extensions. Путь можно задать через FPT_PROBE_CHROME, временную рабочую папку — FPT_PROBE_WORKDIR. Скрипт не загружает Funcy и не обращается к FunPay. Обычный установленный branded Chrome в этой среде не загрузил тестовый service worker через CLI; итог получен в Chrome for Testing.

## Что этим не проверено

- Реальная доставка/получение сообщений FunPay, OTP на аккаунте Steam, purchases/refunds/partial/refill, наличие товара, фактические сторонние API и права пользователей.
- Полный Chat Sync, Telegram MTProto, вход с 2FA, текущий Fragment/Roblox/Steam web flow и подпись/отправка реальных TON-транзакций.
- Будильник создан, но точность его срабатывания во сне, при закрытом браузере и на минимальном Chrome 120 не тестировалась. persistAcrossSessions из Chrome 151 не считается гарантией всей поддерживаемой базы.
- Тестовый checkpoint демонстрирует механизм хранения после остановки worker, а не правильность ещё не написанных портов или фактическую exactly-once выдачу.
- Полный набор тестов Funcy не запускался: runtime не менялся. Отдельная проверка данных отчёта находится в checks/validate.py.

## Целостность материалов

[Проверка данных отчёта](checks/validate.py) завершилась без ошибок; результат записан в [validation-results.json](checks/validation-results.json). Она сверяет числа и ID каталога, Markdown/CSV/JSON, локальные ссылки, строки и хеши доказательств, охват сценариев и состав защищённых релизов, а также неизменность выбранных файлов Funcy. Это проверки материалов исследования, не тесты работоспособности плагинов. `git diff --check` не нашёл ошибок; существующие отслеживаемые файлы репозитория не изменены.

## Приёмка будущего переноса

Для каждого выбранного модуля нужны его бизнес-сценарии из карточки, в том числе остановка worker до/после записи попытки, два события одного заказа, переключение аккаунта, ручная правка, отзыв/возврат между проверкой и отправкой, частичный/неопределённый результат внешнего API. Для денежных запросов отдельно доказать сохранение attempt/result до продолжения и отсутствие слепой повторной покупки. Эти испытания в данном исследовании не выполнялись.
