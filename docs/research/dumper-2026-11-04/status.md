# Автодемпер — статус реализации (2026-11-04)

Страница «Автодемпер» (раздел «Лоты и продажи») с настройками каждого лота в стандартном окне
Funcy. Заменяет прежнюю идею демпера вкладкой массового редактора.

## Модули

| Файл | Назначение |
| --- | --- |
| `offscreen/dumper_parsers.js` | Разбор выдачи `/lots/`, `/chips/`, карточки предложения и своей формы `offerEdit` |
| `background/dumper_market.js` | Идентификатор предложения, нормализация выдачи, строгий отбор с причинами |
| `background/dumper_price.js` | Стратегии, минимум/потолок, лимиты, места с равными ценами, коэффициент калькулятора |
| `background/dumper_history.js` | История в IndexedDB `funcy-dumper-history`: 30 дней / 50 000 записей на аккаунт |
| `background/dumper_service.js` | Правила по аккаунту, проверка, включение, проходы, намерения записи, паузы, 429 |
| `content/ui/dumper_page.js`, `css/dumper.css` | Страница и окно лота (Цена / Конкуренты / История) |

Сообщение `fptDumper`: `list, get, save, check, enable, resume, disable, remove, copy, setGlobal, history, run`.
Задание `fpToolsDumperRun` в общем планировщике; после перезапуска — сверка незавершённых записей и один
актуальный проход. Ключ `fpToolsDumper` и история не переносятся импортом настроек и синхронизацией профилей.

Изменения в общем коде: `chip_writer` (ожидаемая цена `expect.price` и перечитывание строки после сохранения
раздела), `pricing_service` (автопересчёт пропускает лоты, которые ведёт демпер; `costOf` экспортирован).

## Проверено на публичной разметке FunPay (гость, только чтение)

- `/lots/1217/` (Spotify Premium): схема `[{type, 4}, {time, 5}]`, условий нет — региона и способа активации в схеме нет;
  `a.tc-item[data-f-type="individual"][data-f-time="1 месяц"]`, `.tc-price[data-s="162.24776"]`, текст `162.25 ₽`;
  счётчик раздела 1539 = строкам в HTML (постраничность только интерфейсная).
- `/lots/1355/`: поле `type` с условием `{subscription ∈ ["с подпиской"]}`; строки «без подписки» не имеют `data-f-type`;
  счётчик 4301, в HTML 3001 строка (3000 уникальных) — выдача обрезается, такой сбор помечается неполным;
  продвигаемое предложение встречается дважды; признак автовыдачи — `data-auto="1"` и `.auto-dlv-icon`.
- `/chips/26/`: `.tc-price[data-s="0"]` при видимой цене `0.63 ₽` — `data-s` это сортировка; `data-server`, `data-side`,
  ID `продавец-игра-раздел-сервер-сторона`; заголовок «Цена/1кк»; `.tc-amount[data-s]` — остаток.
- Карточка `lots/offer?id=…`: `.param-list .param-item` (h5 + значение), раздел по ссылке `/lots/<node>/`,
  продавец `.chat[data-seller]`; тот же класс `.param-item` у блока оплаты и рейтинга — они отфильтрованы.

Фикстуры: `tests/fixtures/dumper/*.html` (без скриптов, выдача урезана, csrf заменён).

## Не подтверждено и ждёт приёмки на реальном аккаунте

1. **Своя форма `offerEdit`**: что значения `fields[type]`/`fields[time]` (или подписи вариантов) совпадают с
   `data-f-*` выдачи после нормализации. Если нет — все конкуренты исключатся с причиной «Другое значение», цена
   не изменится (безопасный отказ), но правило будет бесполезно.
2. **Калькулятор**: `lots/calc` (nodeId, price) используется расширением и раньше; `chips/calc` (game, price) —
   по образцу FunPayAPI, на живом аккаунте не проверялся. Без ответа калькулятора запись запрещена.
3. **Своя строка в выдаче под авторизацией**: для валюты комиссия и единица подтверждаются только совпадением
   расчёта калькулятора с ценой своей строки; неактивное предложение валюты не демпингуется.
4. **Валюта витрины**: выдача читается с cookies пользователя; цена конкурентов и своя строка берутся в одной
   валюте (символ единицы). Страница не на русском языке останавливает сравнение.

### Порядок приёмки

1. Сохранить правило на обычном лоте, «Проверить» — без включения. Сверить: свои значения полей в блоке
   «Параметры раздела», список «Подходят», причины исключения, «Комиссия сверена с вашей строкой».
2. То же для валютного предложения (активного). Задать точность цены явно.
3. Наблюдение: включить на одном лоте с широким минимумом и шагом, посмотреть «Историю» 2–3 прохода.
4. Ручная правка цены на FunPay → правило встаёт на паузу «цену изменили вне демпера».
5. Отдельно зафиксировать: результаты тестов и подтверждение на реальном FunPay (дата, лот, что видно в истории).
