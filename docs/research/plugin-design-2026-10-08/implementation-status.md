## Модули

- **Расписания** — недельные окна в сохранённой IANA-зоне, ночные окна, DST «по настенным часам», предпросмотр переходов со смещением, черновик → явное включение, один alarm, без проигрывания пропущенного. «Управление лотами» → «Расписание». `lot_schedule_rules.js`, `lot_schedule_service.js`, `content/ui/lot_automation_page.js`.
- **Цены и прибыль** — floor с минимальной прибылью, маржой и расходами, наценка ≠ маржа, шаг вверх с перепроверкой, потолок ниже floor → блокировка продаж; предпросмотр от свежих форм, применение только строк предпросмотра с `expect`; автопересчёт — отдельное согласие, ≤10% за проход, пауза после ручной правки. `pricing.js`, `pricing_service.js`.
- **Остатки** — остаток склада FunPay с временем проверки и ошибкой; только показывается, лот по нему не включается и не выключается; состояние управления в строке лота (причины, пауза, «Разрешить включать», «Не включать автоматически»).
- **Напоминания об отзыве** — одна задача на новый заказ после включения, только при проверенной выдаче (все части confirmed) и подтверждении покупателем; любой отзыв отменяет, неизвестное откладывает; лимит на чат резервируется атомарно; неясная отправка расходует лимит и не повторяется. Третий блок «Отзывы и бонусы». `review_reminders.js`, `content/ui/review_reminder_block.js`. Бонус за отзыв получил дедупликацию и проверку чёрного списка.
- **Проблемные заказы** — вкладка «Заказы и выдачи» в «Автовыдаче»: фильтры по решению, карточка с этапами, частями, историей; только допустимые действия с проверкой ревизии; ручная отметка хранится отдельно; удержание продавца. `order_commands.js`, `content/ui/orders_view.js`.
- **Поставщики** — модуль удалён полностью (2026-10-09): раздел, режим автовыдачи «Поставщик», закупка из карточки заказа, хранилища журнала и фактические затраты в «Финансах». Сохранённые настройки `fpToolsSupplier*` удаляются при обновлении (`retired_integrations.js`).

## Что намеренно не включено или ждёт проверки

- **Подтверждение доставки сообщения.** Формат ответа runner не закреплён реальными фикстурами. Если наше сообщение в ответе не найдено, часть получает `accepted`, а не `confirmed`; тогда напоминание об отзыве не планируется. Нужна обезличенная запись ответа `/runner/` на отправку сообщения.
- **Отсутствие отзыва.** `absent` ставится только при узнаваемом блоке отзыва без оценки и текста. Нужна реальная страница заказа без отзыва и с отзывом; до этого напоминания будут откладываться как `unknown`.
- **Следующие этапы плана**: локальные пулы с FIFO-резервом, конкурентный демпинг, исключения расписаний по датам.
- **Мультиаккаунт** — автоматизация обслуживает текущий подтверждённый аккаунт; ручной вход между чтением и записью полностью не исключён.

## Проверка

`node --test tests/*.test.js`: новые наборы — деньги и факты заказа, журнал v2 (в памяти и в реальной IndexedDB Chrome), отправитель, контроль аккаунта, исполнитель, сверка, очередь лотов, resolver, расписания (включая DST), цены, напоминания, команды заказов, браузерные проверки новых экранов. Те 7 UI-тестов, что падали до начала работы (геометрия «Автовыдачи», три теста «Финансов», браузер «Управления лотами», утечка темы, анимация вкладок), падают и сейчас по тем же причинам. Фоновый модуль загружен в Node с имитацией API Chrome: все новые обработчики отвечают. Брендовый Chrome не загружает распакованное расширение из командной строки, поэтому полный запуск в браузере с FunPay этой проверкой не покрыт.
